# ComfyUI-OpenClaw v1.1.0

Release date: 2026-08-19

This release consolidates the compatibility, startup reliability, security posture,
operator workflow, architecture, and verification work completed since `v1.0.0`.

## Highlights

### Current ComfyUI and Desktop compatibility

- Refreshed the active host baseline to ComfyUI `3aba3dae` / `0.33.0` and the
  standalone frontend to `1.52.1`.
- Separated legacy Desktop `0.9.4` fixed-bundle behavior from current
  Comfy-Desktop `1.0.32-rc.1` managed-install behavior, whose hosted component
  versions remain installation-specific.
- Added safe current-Desktop presence detection without treating bridge presence as
  authorization for privileged capabilities.
- Excluded ComfyUI's `datasets` user-data root from model inventory and Model Manager
  destinations.
- Documented native ComfyUI ownership for video, webcam, audio, text-to-speech, and
  workflow workspace capabilities instead of duplicating host-owned functionality.

### Startup reliability and security posture

- Added typed, redacted startup lifecycle outcomes for readiness, retries, fatal
  failures, timing, and optional warmup degradation.
- Centralized process-static deployment and security decisions in an immutable,
  secret-free effective posture snapshot.
- Split bootstrap lifecycle and route registration into focused service packages while
  preserving legacy import identities and public route behavior.
- Restored packaged route imports and added loader-realistic regression coverage that
  verifies real route-family registration on the first startup attempt without retry,
  thread, alias, or process-state leakage.
- Replaced the tracked systemd environment file with a public-safe
  `openclaw.env.example` template while keeping secret-bearing environment files out of
  version control.

### Parameter Lab and output interoperability

- Restricted Parameter Lab creation and persistence to bounded scalar values and
  rejected nested, non-finite, oversized, or ambiguous inputs.
- Correlated queued Parameter Lab runs through exact request-ID receipts and failed
  explicitly on unsupported, malformed, busy, or ambiguous host queue shapes.
- Recognized advanced 3D `result` references as bounded output links without rendering
  binary content or consuming unrelated metadata.
- Preserved optional hash-backed output references while keeping asset-service-only
  identifiers as explicit compatibility fallback states.

### Maintainability and architecture

- Decomposed large API route and configuration modules behind stable facades and
  machine-checked contracts.
- Split connector command routing and Slack/Feishu ingress, installation, and delivery
  responsibilities into focused owner modules.
- Split frontend API clients and Settings-tab responsibilities while preserving the
  shared singleton, DOM behavior, and existing host compatibility fallbacks.
- Added a dependency-light production import verifier that detects unknown ownership,
  forbidden dependency direction, cycles, and unreviewed dynamic imports without
  importing application modules.
- Hardened selected exception boundaries so cancellation, compatibility fallback,
  public status mapping, and redacted diagnostics remain explicit.

### Verification and supply-chain hardening

- Added pinned incremental Ruff and Mypy enforcement that blocks new production-code
  debt while keeping existing debt governed.
- Added deterministic scale baselines for large jobs history, connector summaries, and
  frontend output normalization.
- Promoted the governed backend coverage floor from 45% to 55% with retained release
  evidence and hotspot ownership checks.
- Made contract digests stable across Windows and Linux line endings.
- Expanded exact high-risk classification across startup loader, route-bootstrap,
  registration, contract, and import-fallback owners without broad path escalation.
- Bound release and high-risk acceptance to clean exact candidates and added regression
  coverage for worktree cleanliness.
- Hardened frontend dependency validation across the complete lockfile tree and updated
  the vulnerable transitive `nanoid` resolution to a patched release.

## Compatibility

- Python 3.10, 3.11, 3.12, and 3.13 are supported and validated.
- Python 3.14 remains best effort; versions below Python 3.10 are unsupported.
- The OpenClaw frontend test harness continues to require Node.js 18 or newer.
- Existing `Moltbot*` node class identities, legacy `/moltbot/*` route aliases, and
  `MOLTBOT_*` environment aliases remain available for compatibility.
- No intentional breaking change was made to serialized node identities or public route
  contracts in this release.

## Upgrade notes

1. Update the custom node through ComfyUI-Manager or pull the latest `main` branch.
2. Restart ComfyUI so the Python package and frontend extension reload together.
3. If using the systemd deployment example, copy values into a local secret-bearing
   environment file; do not track or publish that file.
4. Review the current
   [compatibility matrix](compatibility_matrix.md) and
   [support policy](support_policy.md) when upgrading the host runtime.

## Validation

The release candidate is validated through the repository's required Windows Full Gate,
including secret scanning, pre-commit checks, static and architecture governance,
backend tests, adaptive adversarial validation, dependency audits, and Playwright E2E.
