# ComfyUI-OpenClaw v1.2.0

Release date: 2026-09-07

This release consolidates the frontend delivery, real-host verification, host
compatibility, configuration governance, and architecture work completed since `v1.1.0`.
Its headline change is that the pack no longer ships its own test suite to your browser.

## Highlights

### The frontend test suite is no longer served to browsers

- The frontend test tree moved out of the directory this pack registers with ComfyUI.
  ComfyUI publishes every JavaScript file beneath a registered web directory and its
  frontend imports all of them without filtering, so those files were previously fetched
  and executed by every browser on every page load, where they failed to resolve their
  test-runner imports.
- Entries served by this pack dropped from `90` to `56`, all of them runtime modules. The
  wasted requests, the standing cluster of console errors they produced, and the exposure
  of the internal test layout to anyone reading `/extensions` are all removed.
- A guard test now fails if any test file or test directory reappears under the served
  directory, reading the directory name from the package rather than hardcoding it, so the
  layout cannot regress quietly.
- The served directory name is unchanged, so existing installations keep resolving the
  same `/extensions` path.

### Real-host frontend compatibility verification

- Added a pinned real-host frontend compatibility smoke lane that starts a pinned ComfyUI,
  loads this pack alongside a peer fixture, and checks plugin load, sidebar stamping,
  Settings and Jobs surfaces, the sidebar width floor, promoted-widget round-tripping,
  annotated temporary result links, and custom-to-custom shared-mount handover.
- The lane has now actually been executed against a running ComfyUI rather than only
  reviewed. Both pinned frontend subjects were confirmed in the browser from the
  frontend's own reported version: the bundled `1.51.9` and the reproducible standalone
  release `1.54.3`.
- The lane verifies the standalone release against a digest pinned from published release
  metadata before the host is allowed to see the artifact, and refuses a mismatch.
- Browser errors are now attributed by the failing request's URL rather than by console
  message text, because the browser does not name the failing file in its console output.
  Requests the host makes for its own optional files, and errors raised by other installed
  packs, are reported separately instead of being charged to this pack. A check that
  deliberately provokes a failing request declares it, matched whole and scoped to that
  check alone.
- Independent review and the first real executions together found and closed a series of
  lane defects, including one where the lane started a host that could not load the
  product at all.

### Host compatibility and evidence separation

- Refreshed the reviewed host baseline to ComfyUI `31dfbd4c` / `0.34.0` with its bundled
  frontend pin `1.51.9`, and recorded the reproducible standalone frontend release
  `1.54.3` separately from the later reviewed frontend source head.
- Compatibility evidence is split into independent source-review, repository-validation,
  and real-host states, so a reviewed checkout can no longer read as a validated running
  host. Real-host validation remains `pending` until a lane run carrying a run identifier
  succeeds against the pinned anchor.
- Legacy Desktop and current managed-install Comfy-Desktop remain modeled as separate
  references rather than being cross-wired into fixed hosted-version claims.
- Annotated Advanced 3D `result` references, including the `<path> [temp]` form the
  current preview nodes report, are recognized as bounded view links carrying the host
  directory type.

### Configuration and environment policy governance

- Legacy environment aliases are centralized, and alias provenance is enforced at the use
  site rather than assumed from a declaration.
- The environment policy analyzer was substantially hardened: it now models Python binding
  semantics, guarded loop exits, `try` region transitions, builtin scope execution,
  iterator and closure provenance, container and execution provenance, deferred bindings,
  competing import origins, and conditional builtin aliases, and it fails closed rather
  than guessing when provenance cannot be established.
- Canonical worker fallbacks and deterministic static semantics are preserved across those
  changes, so hardening the analyzer did not change what the runtime resolves.

### Architecture, imports, and quality ratchets

- Import helper edges, keyword targets, and package and root helper targets are now
  governed deterministically, and package resolution is enforced to be deterministic.
- Public names and comments are held to a ratchet that blocks new internal-code-only
  naming while leaving untouched existing debt from blocking unrelated work.
- Type annotations were modernized in the three best-covered packages.
- Exception boundary reporting and builtin exception diagnostics were tightened so
  failures stay explicit instead of being flattened.

### Frontend and operator surfaces

- Admin console fields render as text, so values cannot be interpreted as markup.
- The sidebar enforces a reversible minimum width, preserving a wider host or user width
  instead of reducing it to the floor.
- Reusable mount ownership is isolated, so handing the shared mount to another custom tab
  is clean even when that tab provides no destroy callback.

### Verification governance

- Added transactional coverage floors and pinned import exception removal.
- The acceptance gate's stage contract is aligned with its frontend unit step, and CI
  enforces the project-local Python interpreter.
- Connector workspace artifacts are isolated during testing.

## Compatibility

- Python 3.13 is the current locally validated baseline.
- Python 3.10, 3.11, and 3.12 remain compatibility targets pending current exact-version
  evidence.
- Python 3.14 remains best effort; versions below Python 3.10 are unsupported by the
  package contract.
- The OpenClaw package and test harness continue to require Node.js 18 or newer.
- Existing `Moltbot*` node class identities, legacy `/moltbot/*` route aliases, and
  `MOLTBOT_*` environment aliases remain available for compatibility.
- No intentional breaking change was made to serialized node identities, public route
  contracts, or the `/extensions` path this pack is served under.

## Upgrade notes

1. Update the custom node through ComfyUI-Manager or pull the latest `main` branch.
2. Restart ComfyUI so the Python package and frontend extension reload together.
3. If you previously installed this pack from source, a stale `web/tests` directory may
   remain inside the installation. Removing it completes the frontend delivery fix; a
   clean install or a `git`-tracked update removes it for you.
4. Review the current [compatibility matrix](compatibility_matrix.md) and
   [support policy](support_policy.md) when upgrading the host runtime.

## Validation

The release candidate is validated through the repository's required Windows Full Gate,
including secret scanning, pre-commit checks, static and architecture governance, backend
tests, adaptive adversarial validation, dependency audits, and Playwright E2E.

In addition, and for the first time in this project, the pinned real-host frontend smoke
lane was executed against a running ComfyUI `0.34.0` host rather than only reviewed. Both
pinned frontend subjects reported every check passing. That host matched the pinned anchor
on release version rather than on the exact source commit, and the runs produced no run
identifier, so the published real-host evidence state deliberately remains `pending`.
