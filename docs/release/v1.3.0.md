# ComfyUI-OpenClaw v1.3.0

Release date: 2026-10-13

This page records the release-time evidence. For the current pinned host subjects and
qualification status, see the [compatibility matrix](compatibility_matrix.md).

This release consolidates the work completed since `v1.2.0`, including the `1.2.3` registry
update, which shipped without its own release page. Its headline changes are that trigger
callbacks and scheduled chat results are now actually delivered, that external process
spawning and the registry package were hardened, and that the refreshed ComfyUI and frontend
subjects were qualified on a running host.

## Highlights

### Trigger callbacks and scheduled chat results are delivered

- Trigger requests accepted a callback and approval records stored it, but the shared
  submission path never used it, so no result was ever delivered. Trigger requests and
  approval-gated runs that name a callback now deliver their result to it.
- The callback's format is validated before any side effect, and split deployments refuse
  it. The exact-host allowlist (`OPENCLAW_CALLBACK_ALLOW_HOSTS`; none configured means no
  delivery) and the SSRF policy apply when the result is delivered, and the result watcher
  waits about five minutes for the job. Responses report the callback status.
- Schedules with a Telegram, Discord, Slack, or Feishu/Lark delivery target previously
  submitted their job and then dropped the target. Each run now records one durable delivery
  intent, keyed by the schedule's idempotency key so a retried tick reuses it.
- The connector claims those deliveries with a one-time lease, enforces the platform
  allowlists, waits for the job, and sends the result, or a short failure or timeout notice
  that never copies job errors or outputs. It then acknowledges the outcome; throttled,
  server, and transport acknowledgement failures are retried so a sent result is not posted
  again; a connector that stops between sending and acknowledging can still post it twice.
  Webhook and custom targets have no connector adapter and are recorded as undeliverable.
- The worker runs only when the connector's admin token is set and a supported platform is
  running, and polls every `OPENCLAW_CONNECTOR_SCHEDULE_DELIVERY_POLL_SEC` seconds (default
  `15`, clamped to `5..300`). Schedule run history includes a delivery summary. See
  [Connector](../connector.md) and the [API contract](api_contract.md).

### Process spawning hardened and the registry package narrowed

The Comfy Registry flagged `1.2.3` under its command-injection policy. This release reviews
every shipped place that starts a process and narrows what the registry archive contains.

- Filesystem allowlists for external tools are checked by whole path components after links
  and case are resolved, so a sibling such as `<allowed>-evil` no longer passes. Relative
  values are checked against the tool's working directory.
- Tool definitions whose program contains a placeholder or is a relative path are skipped.
  Bare program names resolve only from absolute `PATH` entries, the absolute path is what
  gets started, and Windows batch targets are refused.
- Argument values containing control characters, or that would start an argument with `-`,
  are rejected; rejection messages name the argument, not the value.
- The default tool allowlist now ships empty. The definition rules and an example are in
  [Runtime Hardening and Startup](../runtime_hardening_and_startup.md).
- The transform worker starts with an explicit environment allowlist, and the operator
  doctor reads the pip version from package metadata instead of starting pip.
- Registry archives built by `comfy node publish` now contain the runtime package, web
  assets, data, docs, and the operator scripts the documentation names. Tests and development
  tooling stay in the git repository. A contract test derives the shipped set the way the
  publishing tool does and keeps the shipped modules that start processes equal to a
  reviewed list.
- The operator doctor finds the pack root from `pyproject.toml` and reports source-checkout
  files as not applicable in an installed package.

### Host compatibility refreshed and qualified on a running host

- The reference anchors moved twice during this cycle and now follow ComfyUI `0.39.0`
  (source head `8010b48d`, bundled frontend `1.55.14`) and the standalone frontend release
  `1.57.0`. The later reviewed frontend source checkout remains a separate, unexecuted
  subject.
- Both current frontend subjects passed the real-host browser spec on ComfyUI `0.39.0` with
  no skipped case. The standalone subject's served files matched a release archive with the
  pinned size and SHA-256. The compatibility matrix records the paired campaign with its run
  identifier; both Desktop surfaces stay `pending`.
- During the cycle the previous core `0.37.0` was also qualified with its bundled frontend
  `1.53.6` and the standalone release `1.55.11`; that campaign remains historical evidence.
- Switching from OpenClaw to another sidebar tab no longer snaps the sidebar back to its
  earlier width. The host splitter pins a dragged width while OpenClaw is open, and OpenClaw
  used to restore its captured values over it. It now releases only the sizing it applied and
  the element still holds, and a real-host check drags the host's own gutter to prove it.
- Promoted-widget checks now require a real host-created subgraph binding, an OpenClaw edit,
  and readback of the projected value and the effective inner prompt.
- A saved 3D output exposed through both `3d` and legacy `result` appears once in Python
  history parsing and the Jobs view. Host-enriched output identifiers are treated as
  metadata, and the current shapes (`3d` items with camera and model information, Preview3D's
  legacy `result` item, optional per-file metadata) are pinned in both parsers.
- The real-host lane no longer passes `--listen`, which had made the product classify itself
  as network-exposed and refuse the lane's own browser; the bind is proven from the host's
  startup line instead. Aborted requests are attributed by the browser's structured failure
  kind, and the scheduled release download follows the pinned version and digest policy.

### Operator alerts and request deadlines

- A dismissed alert can appear again once its condition has ended and recurs. Connectivity
  and high-load alerts retire automatically on recovery, a durable connectivity error is
  written only after repeated consecutive failures, and a false startup warning about a
  missing host API shim was removed.
- Browser requests keep OpenClaw's deadlines across host fetch adapters. Host timeouts report
  as timeouts without retrying the timed-out request, caller cancellation stays distinct, and
  ordinary eligible GET failures keep bounded retries.

### Verification governance

- The backend test gate now also runs the suites kept in test subdirectories, including the
  connector, security, and contract suites. It loads them by their full module name, rejects
  a module that resolves to a different file, and a guard test fails when a test module is
  not reached. Two suites that replaced modules process-wide at import time were fixed.
- Type-alias policy checks are version-aware, so older interpreters carry real coverage
  instead of passing on a fixture they cannot parse.
- A fix verified by a CI workflow must be shown passing on the branch it lands on.
- Harness retry evidence survives page recovery reloads, and high-risk acceptance receipts
  declare their review mode.
- The support policy states what is actually validated on Python 3.10-3.12.

### Dependencies

- A high-severity advisory in the frontend development dependency `source-map-js` is patched
  through a compatible lockfile resolution, and `@vitest/mocker` was updated.

## Compatibility

- Python 3.13 is the current locally validated baseline.
- Python 3.10, 3.11, and 3.12 remain compatibility targets pending current exact-version
  evidence.
- Python 3.14 remains best effort; versions below Python 3.10 are unsupported by the
  package contract.
- The OpenClaw package and test harness continue to require Node.js 18 or newer.
- Existing `Moltbot*` node class identities, legacy `/moltbot/*` route aliases, and
  `MOLTBOT_*` environment aliases remain available for compatibility.
- No intentional breaking change was made to serialized node identities, existing public
  route contracts, or the `/extensions` path this pack is served under. New admin-plane
  routes for scheduled delivery are documented in the [API contract](api_contract.md).
- Behavior that may need attention: external tool definitions that relied on relative
  programs, placeholders in the program, batch files, or leading-dash argument values are now
  skipped or rejected (`execution_error`); transform modules no longer see environment
  variables outside the worker allowlist; callbacks attached to triggers and approvals now
  fire, to hosts listed in `OPENCLAW_CALLBACK_ALLOW_HOSTS`.

## Upgrade notes

1. Update the custom node through ComfyUI-Manager or pull the latest `main` branch.
2. Restart ComfyUI so the Python package and frontend extension reload together.
3. If you run external tools, supply your reviewed definitions with
   `OPENCLAW_TOOLS_CONFIG_PATH` and check them against the rules in
   [Runtime Hardening and Startup](../runtime_hardening_and_startup.md); the shipped
   allowlist is empty.
4. To deliver scheduled results to chat, run the connector with
   `OPENCLAW_CONNECTOR_ADMIN_TOKEN` set and the target platform enabled and allowlisted; see
   [Connector](../connector.md).
5. Registry installs no longer include the test suite or development tooling. Use a git
   checkout to run the tests.
6. Review the current [compatibility matrix](compatibility_matrix.md) and
   [support policy](support_policy.md) when upgrading the host runtime.

## Validation

The release candidate is validated through the repository's required Windows Full Gate,
including secret scanning, pre-commit checks, static and architecture governance, backend
tests, adaptive adversarial validation, dependency audits, and Playwright E2E.

The pinned real-host browser spec was executed against a running ComfyUI `0.39.0` with its
bundled frontend `1.55.14` and with the standalone release `1.57.0`. Both subjects passed
all eleven cases with no skipped case, including the new sidebar-width check, which also
failed as expected when the earlier sidebar release code was substituted.
