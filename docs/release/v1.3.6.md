# ComfyUI-OpenClaw v1.3.6

This release qualifies OpenClaw against refreshed ComfyUI host subjects, binds Parameter Lab
plans to their workflow, restores the node context menu entries, fixes request-body reading on
the webhook and preflight routes, and tightens the pack code-safety check. It includes all
changes first published as v1.3.5.

## Host compatibility

- ComfyUI source `da8bd08e` (project `0.46.0`) was qualified with its bundled frontend
  `1.59.11` and standalone frontend release `1.61.8` in an isolated CPU host on 2026-11-24.
- Each frontend passed all eighteen browser cases without skips, unexpected results or
  retries. Besides the earlier sidebar, settings, promoted-widget, node-ID and replay cases,
  the campaign covers workflow binding, the node context menu and the absence of extension
  warnings.
- The bundled `1.59.x` line does not carry the per-workflow graph changes of the `1.61.x`
  release, so the two frontends do not share one graph model. Workflow binding was checked on
  both.
- Either Desktop surface, the published core tag and its patch tags, and frontend patch
  `1.59.14` remain separate, unexecuted subjects. No GPU or provider generation was part of
  this host campaign.

See the [compatibility matrix](https://github.com/rookiestar28/ComfyUI-OpenClaw/blob/v1.3.6/docs/release/compatibility_matrix.md) for exact anchors and evidence scope.

## Parameter Lab

- Each plan is bound to the workflow it was generated or loaded from. Running, replaying or
  queueing it after another workflow becomes active stops with a message before any value is
  written or any prompt is queued, instead of changing the workflow that happens to be open.
- A plan whose workflow changed while it was being built is rejected, and the plan must be
  rebuilt from the current workflow.

## Node context menu

- The `OpenClaw:` entries (Inspect, Doctor, Queue Status, Compare and Settings) now appear in
  the node right-click menu. They were registered after the frontend's one-time extension
  setup and could be missing entirely.
- On frontends that provide the node-menu hook, the entries are added through it, which also
  avoids the frontend's deprecated monkey-patching warning. Frontends without the hook keep
  the previous fallback.

## Request handling

- Webhook, webhook validation and submission, and preflight requests read a body that arrives
  in several network chunks in full, up to the 64 KiB limit, before parsing it or checking its
  signature. Previously only the first chunk could be read, so a valid request could fail its
  JSON or signature check.

## Pack code safety

- Pack import and registry quarantine verification reject Python members that call the
  dynamic-execution functions. The check now also catches such a call written with whitespace
  between the function name and its parenthesis, which it previously missed.
- Every pack that was rejected before is still rejected, with the same message. A pack that
  only passed because of that whitespace is now rejected.

## Operator doctor

- The `pre-commit` availability check asks the import system whether the package can be found
  instead of importing it, so running the doctor no longer executes the package's startup code.
  Results are unchanged for a working or a missing installation.

## Source scanner findings

- A variable name in the Slack connector settings and the pack check's own deny-list were read
  by automated source scanners as privilege escalation and dynamic execution. Both were
  rewritten without changing behavior.

## Development tooling

- The CI browser lanes support Ubuntu 26.04 runners, and the Playwright test dependency is
  `1.65`. The mocked browser test server listens on loopback only.
- When a real-host validation step fails, its output ends with a bounded, redacted tail of the
  failing command's output, with credentials, tokens and home-directory paths masked.
- These are development and test changes; using the installed custom nodes does not require
  them.

## Upgrade notes

Update the custom-node pack through ComfyUI-Manager or Git, restart ComfyUI, and reload the
browser. No configuration or storage-schema migration is required.

OpenClaw continues to use bounded `/history` and `/view` output access; direct Asset API
adoption remains deferred. Desktop runtime qualification is tracked separately.
